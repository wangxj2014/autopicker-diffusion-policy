# Autopicker 苹果果墙场景

开发版现已分离模型与程序：`autopicker_apple_orchard.usd` 只保存模型、材质、相机、关节和物理设置，采摘与相机重建从同目录 Python 文件加载。开发时请一起保留以下文件；仅打开开发版 USD 不会自动采摘。

| 文件 | 职责 |
| --- | --- |
| `autopicker_apple_orchard.usd` | 设备、果树、苹果、草地、相机和物理设置 |
| `autopicker_apple_pick.py` | 采摘控制、接果、树体振动与落果；参数在 `DEFAULTS` 中 |
| `autopicker_camera_viewer.py` | 四路 RGB、四路深度和重建窗口 |
| `autopicker_depth_fusion.py` | 同步 RGB-D 配准、固定世界坐标累积和点云显示 |
| `autopicker_runtime.py` | 启动、暂停、Stop/Play 和资源清理 |
| `autopicker_start.py` | 开发版统一启动入口，每次运行重新加载最新 Python 源码 |
| `autopicker_package.py` | 按需生成单文件演示版 |

单文件交付使用生成的 `dist/autopicker_apple_orchard_demo.usd`；该文件内嵌当次打包的程序，复制这一个 USD 即可在 Isaac Sim 中播放。

- 保留原 autopicker_v4 的机身、四组机械臂和原有末端，未添加柔性抓取头。
- 设备两侧各一面平面树型果墙，每侧 3 棵树，共 396 个独立苹果。每棵树约高 3.12 米、宽 2.24 米、厚 0.28 米。
- 两侧果墙在上一版基础上各向设备靠近 **5 cm**，相向树冠外缘之间的净距改为 **2.900 米**。以设备为中心对称布置，固定机身 `base_link` 到每侧树冠的净距均为 **0.68659 米（约 68.66 cm）**。均沿场景横向 Y、按静止时的外包围盒计算，伸出的活动机械臂不计入机身净距。
- 单位为米，Z 轴朝上。车辆已放到地面高度。
- 地面为草地：绿色地表和约 2–6 cm 高的草叶全部内嵌在 USD 中。保留原地面碰撞面；草叶仅用于显示，不参与碰撞。

## 四路 RGB 与深度相机

四个原 `cam_link` 已升级为相机组件：外观直接使用原来的 `cam_link/visuals` mesh，保留刚体和安装关节，增加能实际渲染图像的 `Camera` 子节点。四个 `Camera` 的辅助图标已隐藏，场景中只显示原外壳；这不影响相机成像。相机固定在安装架上，随机械臂运动，左右两侧分别朝向对应果墙；不会自动追踪目标。

| 画面位置 | 机械臂 | USD 相机路径 |
| --- | --- | --- |
| 左上 | 左上臂 L_up | `/World/Autopicker/root_joint/L_up_cam_link/Camera` |
| 右上 | 右上臂 R_up | `/World/Autopicker/root_joint/R_up_cam_link/Camera` |
| 左下 | 左下臂 L_down | `/World/Autopicker/root_joint/L_down_cam_link/Camera` |
| 右下 | 右下臂 R_down | `/World/Autopicker/root_joint/R_down_cam_link/Camera` |

每路默认 **640 × 480 RGB + 深度、水平视场角 90°**，两个窗口显示上限均为每秒 15 帧。RGB 四路各自复制完整的 `LdrColor` 彩色帧到独立图像缓冲，下一帧就绪前保留上一帧；深度四路使用另外的独立缓冲，RGB 与深度不会在同一框内交替切换。深度与对应 RGB 共用相机和渲染产品，两个窗口都按左上臂、右上臂、左下臂、右下臂排列。

深度来自 `distance_to_image_plane`，表示沿相机光轴、到成像平面的垂直距离，原始数据为 **float32 米制数组，形状 (480, 640)**。深度预览采用固定灰度范围：**0.1 米为白色，5 米及更远为黑色**，无效像素也显示黑色；不按每帧最小/最大值自动缩放。显示范围之外的有效距离仍保存在原始数组中。两个窗口分别更新，不承诺 RGB 和深度的 UI 呈现时间戳完全一致。

光心位于安装坐标系向果墙方向 11 cm 处，以避开外壳。裁剪范围为 0.01–30 米；未模拟具体相机型号的噪声、畸变或曝光响应。实际刷新速度取决于显卡和场景负载，深度计算及图像复制会增加负载。

在 Script Editor 中可读取某一路原始深度，返回的是独立副本；初始化尚未完成时返回 `None`：

```python
import builtins
depth_m = builtins.autopicker_camera_viewer.get_depth('L_up')
```

## 四相机实时配准与果树重建

**Autopicker Fused Point Cloud** 默认显示四台相机逐渐积累的果树点云。全部点转换到固定世界坐标系，单位为米；已经确认的点保留在原位，相机移走后不会消失。随着机械臂带动相机扫到新的区域，树干、枝叶和苹果的表面逐渐补充。

点云使用对应相机 RGB 图像的颜色：每个深度点取同帧、同一像素的 RGB 值，显示苹果、树叶和树干的实际渲染颜色。体素确认后保留首次观测的位置和 RGB 颜色，避免相机切换或光照变化导致旧点颜色闪动。观察中心和比例在打开窗口时按两侧果墙范围固定，不随相机运动或新增点自动缩放、旋转。底部 **Yaw / Tilt / Zoom** 可手动调整观察方位、俯仰和缩放；**Fit** 手动适配已经重建的部分；**Clear reconstruction / restart scan** 清空地图并从下一批数据重新扫描，采摘动作和观察视角不受影响。

四个现有渲染产品共同接入 Replicator 的同步 Writer；每批数据包含四路 RGB、光轴深度、渲染时相机内外参数和共同的 `reference_time`。收到完整的一批后才整体更新，RGB 缺失时保留上一批地图，不借用其他时刻的颜色。通过渲染投影矩阵反投影，再用该帧 `cameraViewTransform` 的逆矩阵变换到世界坐标；不依赖 ICP，也不要求左右相机看到同一块区域。

默认每隔 4 个像素采样一次，保留 **0.1–5 米** 的有效深度，按 **1 cm** 世界坐标体素去重；原始 640×480 深度仍完整保留。一个体素需在两个不同渲染时刻被观察到才加入地图；重复处理同一时间戳不会增加确认次数。30 批内未再次看到的候选点会过期，确认后的点一直保留到 Clear 或 Stop。

只累积两侧果墙范围内的深度点，排除大部分机身和地面。范围使用 USD 果墙包围盒定义，重建表面仍全部由真实渲染深度得到；不会把已有树模型直接复制成点云。曾经扫描过的表面保留，始终遮挡或从未进入相机视场的区域仍为空白。当前没有自动驶向新工位或主动扫描规划，不能保证仅靠现有采摘运动还原整面果墙。

这是历史表面重建。两次观测确认可以减少瞬时运动点，但没有语义分割或动态物体剔除：果实被采走后，地图中已经确认的苹果仍会保留；真实树体振动也可能留下重叠表面。需要重扫时点击 Clear。地图最多保留 40 万确认点和 12 万候选点，达到上限时提示 `MAP FULL`，保留已有地图；Clear 后可重新开始。

显示更新上限为 **15 Hz**，状态行显示确认点数、已融合批数和实际刷新率。预览对新增点增量绘制，调整视角时才重绘完整地图。Pause 保留地图，再 Play 继续追加；Stop 清除旧地图，Play 重新开始。独立相机窗口在暂停状态下首次打开时，需要 Play 后才开始获取同步帧。

本机 RTX 4060 Laptop 8 GB 实测：完整果园、默认采摘速度、三个窗口全部显示并启用 RGB 点云，19.63 秒融合 150 批，平均 **7.64 Hz**；地图从 40,083 点增至 97,730 点。每批配准、累积和深度/点云显示处理耗时中位数约 **73.4 ms**。实际刷新率随场景、地图大小和规划负载变化，不能保证持续达到 15 Hz。

可以在 Script Editor 读取带标定和帧信息的深度，以及当前融合点云：

```python
import builtins
viewer = builtins.autopicker_camera_viewer
frame = viewer.get_depth_frame('L_up')
cloud = viewer.get_point_cloud()
live_cloud = viewer.get_live_point_cloud()
if frame is not None and cloud is not None:
    depth_m = frame['depth_m']
    rgb = frame['rgb']
    intrinsics = frame['intrinsics']
    world_from_camera = frame['world_from_camera']
    points_world_m = cloud['points_world_m']
    colors_rgb = cloud['colors_rgb']
    camera_ids = cloud['camera_ids']
    print(cloud['capture_id'], cloud['reference_time'], points_world_m.shape)
```

返回结果都是独立副本。`get_point_cloud()` 返回累积地图；未收到同步数据、Clear 或 Stop 后为 `None`，第一批候选尚未确认时数组为空。`points_world_m` 为 `N×3 float32`，`colors_rgb` 为逐点对应的 `N×3 uint8` RGB 值（0–255，顺序为红、绿、蓝）。`camera_ids` 对应 `camera_order` 中的首次来源索引，`first_seen_capture_ids` 记录每点首次观测批次；`capture_id`、`reference_time` 表示最近一次融合批次，不代表所有历史点来自这一时刻。`integrated_frames` 是累计融合批数，`accumulated` 为 `True`。

`get_live_point_cloud()` 返回最新单帧四路点云及其 `colors_rgb`，未经累积或果墙空间过滤，其 `capture_id`、`reference_time` 与同批四路 `get_depth_frame()` 一致。帧中的 `rgb` 为 `480×640×3 uint8`，与 `depth_m` 的行列一一对应。参考时间来自渲染器，可能早于读取时刻，不能直接当作墙钟时间或控制器仿真时间。`intrinsics` 使用像素中心整数坐标和 OpenCV 相机方向（右、下、前）；`world_from_camera` 为 USD 行向量矩阵，平移已换算成米，使用前需将 OpenCV 点 `(x,y,z)` 转成 USD 相机点 `(x,-y,-z)`。RGB 四宫格仍独立异步显示，UI 呈现时刻可能不同；点云着色使用同步 Writer 内的 RGB。

点云不写入场景几何，不添加新的场景相机，不参与碰撞，也不会被四台工作相机再次拍摄。开发版由统一入口加载外部转换和显示模块；演示版打包时才将程序嵌入 USD。`autopicker_camera_viewer.py` 单独运行时，需要同目录的 `autopicker_depth_fusion.py`。

## 动作范围

默认保留此前设置的 **3 倍动作速度**，归位、伸臂采摘和回收放果均一起加速。控制参数 `speed_scale` 为 45（加速前为 15），关节驱动响应已同步调整。

采摘接近改为**相对水平面向上倾斜 30°**：先移动到苹果的下方、靠近设备的一侧，再沿斜向上的直线接近。末端伸出方向（`ext` 坐标系的负 Y 轴）在这段接近中也保持 30°，左右两侧镜像处理。默认最后 12 cm 为斜向接近段；接近点受原关节行程限制时，自动缩短至 8、4、2 或 1 cm，角度保持不变。该段速度同样随 `speed_scale` 缩放，当前峰值上限约 0.45 m/s，以保持实际轨迹精度；抓取和放果后仍立即进入下一动作。

选果同时检查 30° 姿态和整段接近路径是否可达，不能满足的苹果会跳过。已修正导入模型约 0.0006° 的轴向数值误差导致可达目标被误判的问题：规划终点位置误差仍要求小于 0.01 mm，方向误差单独要求小于 0.01°。实际执行的方向和位置到位检查继续保留。

当前工位可达苹果从上一版 **28 颗增加至 40 颗**：左下臂 7、左上臂 4、右下臂 18、右上臂 11；已关闭人为抓偏演示并实际采完这 40 颗。默认每 4 次抓偏的演示设置仍保留，因此正常播放的成功收果数会受落果和抓空影响。左右果墙各内移 0–60 cm 的距离扫描显示，过度靠近会超出末端收回范围，不能保证越近越好。

整场 396 颗苹果中，316 颗位于当前水平工位范围之外，另有 40 颗虽在水平范围内，但无法同时满足现有关节行程、30°姿态和完整接近路径。果墙纵向约 6 米，机械臂水平行程为 1.2 米，单靠缩小横向距离无法让全部苹果可达；完整覆盖需要换工位，并解决剩余高度或姿态范围。当前没有自动移动车辆寻找下一工位。一侧采完可达目标后会停止，其他机械臂继续。

已修复进入斜向接近段前的单臂停顿：伸臂从实测关节位置起步，并加入与位置轨迹配套的速度前馈。入口到位门槛按接近段长度的 10% 设置，最大 3 mm；最短 1 cm 接近段仍要求约 1 mm。入口实际方向偏差不得超过 1°，最终抓取点的到位检查继续保留。此前旋转场景中四臂各采 2 颗的对照测试，入口处最长额外等待从约 1.32 秒降至 0.05 秒；当前包含新增边界目标的 40 颗完整测试，最长到位等待约 0.25 秒，无固定停留计时。

四个彩色接果立方体的边长均为 **15 cm**，保存在 `/World/AppleReceivers` 下，打开 USD 后无需 Play 即可看到。每个方块中心位于对应机械臂**放果姿态下的 `ext` 原点正下方 12 cm**，顶面在该原点下方 4.5 cm，留出末端实体所需的间隙。它们分别跟随对应机械臂的 `hor` 滑台实际位移，只沿设备的水平滑轨方向移动，垂直于滑轨的偏置、高度和朝向保持固定。放果时保留本次采摘的 `hor` 位置，其他关节回到原放果姿态，使末端对准随动接果点。

整体旋转或平移 `/World` 后，接果位置会正确转换到父节点坐标，选果范围也按设备自身的滑轨轴计算。调整场景变换后请 Stop → Play 重新初始化。原始未旋转场景的滑轨沿世界 X 轴；旋转场景后，随动方向也会相应旋转。

苹果到达方块上方的放果点后，在同一物理步内移入立方体中心并隐藏，表示已收集；搬运途中保持可见。接果立方体一直保留。Stop → Play 会把收集过的苹果恢复到树上并重新开始采摘。

到位后立即抓取并开始回收，放果后立即选择下一颗苹果并伸臂。已取消原来的低速稳定等待 0.15 秒、抓取后停留 0.5 秒和放果后停留 0.6 秒。仍保留平滑减速及实际末端、关节到位检查；机械臂需要完成实际运动，不会提前吸附远处的苹果。

苹果到位后的成功抓取沿用原演示的视觉吸附方式，没有新增手指或柔性抓手。抓偏时的接触、树体振动和落果行为见下文；此场景用于布局和机械臂采摘动作演示。

普通 USD 软件可查看完整静态模型。自动采摘需要 Isaac Sim 的物理及 OmniGraph 运行环境。

## 抓偏、振动和落果

附 `autopicker_shake_drop_preview.mp4` 作为实际仿真预览；预览为便于展示，设置为每 2 次加入一次偏差。GIF 为同一预览的慢放片段。USD 默认仍为每 4 次。

默认每个机械臂的**第 4、8、12…次尝试**加入沿滑轨方向 **4.5 cm** 的定位偏差，用来演示失败情况；这是人为可控的演示偏差，不是从相机识别误差测得。其余尝试仍以树上的真实苹果位置为目标。每次到达后都比较**实际末端**与**当前苹果**的位置，距离不超过 2.5 cm 才抓取。

- 抓偏且接触苹果或枝干时，对应树体从树根处产生衰减摆动，枝叶及尚未采下的苹果一起运动。附近受影响的苹果约 0.18 秒后脱落。
- 抓空且没有接触时，不触发振动或落果。机械臂空手回收后选择下一颗；掉落的苹果退出采摘列表。
- 落果使用 PhysX 刚体、重力和球形碰撞近似，质量为 0.18 kg；落到草地后保持可见；加入角阻尼和少量线阻尼，近似不规则苹果在草地上的滚动阻力。只有成功送入接果方块的苹果才表示收集并消失。
- Stop → Play 恢复树体、全部 396 个苹果和落果状态。Pause → Play 保留当前进度。

树体摆动采用衰减动画，接触采用末端到苹果/枝干表面的几何距离近似；未建立枝条柔性动力学、真实果柄断裂力或全程机械臂避障。落果使用独立刚体，因此不再跟随摇动的树。树根保持原位，默认摆动频率 3.5 Hz，约 2.5 秒衰减归零。

可通过统一入口传入配置，例如关闭人为偏差、继续保留接触/落果响应：

```python
import runpy
entry = runpy.run_path(r'/home/oem/Documents/Codex/2026-11-19/new-chat/outputs/autopicker_start.py')
task = entry['launch'](config={'grasp_error_every': 0})
```

常用参数：`grasp_error_every` 为每隔几次尝试加入偏差（0 关闭）；`grasp_error_m` 为偏差米数；`shake_degrees` 为振动初始幅值（默认 1.4°）；`detach_delay_s` 为接触至脱落的延时（默认 0.18 秒）。开发版读取控制模块的 `DEFAULTS`，再应用 `launch(config=...)` 的覆盖项。演示版使用打包时的源码默认值，不包含某次启动临时传入的覆盖项。
